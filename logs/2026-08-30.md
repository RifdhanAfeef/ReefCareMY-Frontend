## 主要变更 / Key Changes

### 适配层重构 / Adapter Layer Rework

**中文**：
- 新增 `lib/api/token-store.ts`：`auth-context.tsx` 写 token、`client.ts` 读 token 发请求头，统一到一个模块，避免两处各写一份 localStorage key。
- `lib/api/client.ts`：支持 JSON / `URLSearchParams` / `FormData` 三种 body（后两种不覆盖 Content-Type，交给浏览器自己处理，multipart 的 boundary 尤其不能手动设置）；自动挂 `Authorization: Bearer`；统一从 FastAPI 的 `detail` 字段解析错误文案（字符串直接用，422 的校验错误数组拼接成一句话）。
- `authApi.ts` / `reportsApi.ts`：全部改为真实 fetch 调用，类型与 Swagger schema 一一对应，不再保留 mock/转换层。`AuthResult` 改为平铺结构，贴合 `AuthResponse` 的真实返回。

**English**:
- Added `lib/api/token-store.ts`: `auth-context.tsx` writes the token, `client.ts` reads it for request headers — consolidated into one module so the two files don't each hardcode their own localStorage key.
- `lib/api/client.ts`: supports JSON / `URLSearchParams` / `FormData` bodies (the latter two never get their Content-Type overridden — the browser sets it, and multipart's boundary in particular must not be set manually); automatically attaches `Authorization: Bearer`; uniformly parses error text from FastAPI's `detail` field (a plain string is used as-is, a 422 validation-error array is joined into one readable message).
- `authApi.ts` / `reportsApi.ts`: fully switched to real fetch calls, types matched 1:1 against the Swagger schemas, no mock/mapping layer left. `AuthResult` is now flat, matching the real `AuthResponse` shape.

### 架构决策（需要记录留痕） / Architecture Decisions (worth recording)

**中文**：
- `POST /api/v1/reports` 现在是真实会写库的接口。原先 mock 阶段"打开确认页就自动提交一次"的做法不能再用，否则每次访问/刷新页面都会在生产库里创建一条假报告。改为：`ReportConfirmation` 纯展示组件，通过 URL query string 读取 `reportReference/status/submittedAt/generalLocation/threatCategory`；`reportsApi.submitReport()` 已实现为真实 multipart 请求，等 Epic 2 的多步提交表单接入后，在提交成功回调里 `router.push` 带上这些参数跳转过来即可。
- 登出无对应后端接口（Swagger 中不存在 `/auth/logout`），`auth-context.tsx` 的 `logout()` 改为纯本地清 token，不再调用任何接口。

**English**:
- `POST /api/v1/reports` is now a real, database-writing endpoint. The earlier mock-stage pattern of "auto-submit once the confirmation page loads" can no longer be used — it would create a fake report row every time the page is visited or refreshed against the live database. Changed to: `ReportConfirmation` is now a pure display component that reads `reportReference/status/submittedAt/generalLocation/threatCategory` from the URL query string. `reportsApi.submitReport()` is already implemented as a real multipart request, ready for whenever Epic 2's multi-step submission form is wired up — its success callback just needs to `router.push` here with those params.
- There is no backend logout endpoint (no `/auth/logout` in the Swagger). `auth-context.tsx`'s `logout()` now only clears the local token and calls nothing on the backend.

## 发现的问题 / Issues Found

**中文**：
1. **CORS 白名单**：后端目前只放行 `http://localhost:3000` / `http://127.0.0.1:3000`。本地用非 3000 端口起 dev server 时，注册/登录请求会在浏览器端被 CORS 直接拦下（`curl` 测不出来，因为不走预检请求），排查耗了一些时间。**待办**：确认部署后的正式前端域名是否已加入后端 CORS 白名单，否则线上环境会复现同样的问题。
2. **`expiresIn` 字段**：接口按预期返回，本轮联调看到的值是 3600（1 小时），与此前群里反馈的"返回 60"不一致，但按照约定仍未用该字段做自动登出倒计时，保留观察。

**English**:
1. **CORS allowlist**: the backend currently only allows `http://localhost:3000` / `http://127.0.0.1:3000`. Running the dev server on any other port causes register/login requests to be blocked by CORS in the browser (invisible to `curl`, since it doesn't send a preflight request) — this cost some debugging time. **To do**: confirm whether the deployed production frontend domain has been added to the backend's CORS allowlist, or the same failure will reproduce in production.
2. **`expiresIn` field**: returned as expected during this integration — observed value was 3600 (1 hour), which doesn't match the previously reported "returns 60" bug. Per the team's earlier agreement, this field is still not used for any auto-logout countdown; kept under observation regardless.
